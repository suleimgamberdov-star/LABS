## 1. Цель работы

Приобретение практических навыков по установке и простейшему конфигурированию POP3/IMAP-сервера.

## 2. Исходная конфигурация стенда

Работа выполнялась в виртуальной среде Vagrant/VirtualBox на Rocky Linux 10.

| Узел | Имя | IPv4 |
|---|---|---|
| Почтовый сервер | `server` | `192.168.1.1` |
| Клиент | `client` | `192.168.1.2` |

Для почтового пользователя использовалась учётная запись `suleim06`. В качестве почтового имени в проверке POP3 использовалось `mail.suleim06.net`.

## 3. Установка программного обеспечения

На сервере проверено наличие пакетов Dovecot и Telnet командой:

```bash
rpm -q dovecot telnet
```

В выводе зафиксированы установленные пакеты:

- `dovecot-2.3.21-19.el10_2.8.x86_64`;
- `telnet-0.17-94.el10.x86_64`.

Скриншот результата: `source/screenshots/01_packages_dovecot_telnet.png`.

## 4. Настройка Dovecot

В конфигурации `/etc/dovecot/dovecot.conf` задано:

```ini
protocols = imap pop3
```

В `/etc/dovecot/conf.d/10-auth.conf` задан механизм:

```ini
auth_mechanisms = plain
```

В файле `auth-system.conf.ext` на предоставленном скриншоте показаны системные базы аутентификации:

```ini
passdb {
  driver = pam
}

userdb {
  driver = passwd
}
```

**Ограничение подтверждения:** на одном из предоставленных скриншотов при обращении к `/etc/dovecot/conf.d/10-mail.conf` зафиксировано `Permission denied`. Поэтому итоговое значение `mail_location` для этого файла предоставленными скриншотами не подтверждено. В ходе подготовки предполагалось использовать `maildir:~/Maildir`, однако это значение нельзя считать подтверждённым результатом без дополнительной проверки.

## 5. Настройка межсетевого экрана

На сервере добавлены постоянные правила firewalld для служб:

```bash
firewall-cmd --add-service=pop3 --permanent
firewall-cmd --add-service=pop3s --permanent
firewall-cmd --add-service=imap --permanent
firewall-cmd --add-service=imaps --permanent
```

После этого была введена ошибочная команда `firewall-cmd --add-service=reload`, которая вернула `INVALID_SERVICE: reload`. Затем правила успешно перечитаны корректной командой:

```bash
firewall-cmd --reload
```

На скриншоте отображается успешное выполнение добавления четырёх служб и успешный `reload`.

## 6. Проверка POP3

Выполнено подключение к серверу командой:

```text
telnet mail.suleim06.net 110
```

Сервер ответил приветствием Dovecot. Далее выполнены команды `USER`, `PASS` и `LIST`. Первая попытка аутентификации завершилась ошибкой, после повторного ввода корректных учётных данных сервер ответил `+OK Logged in.` Команда `LIST` вернула:

```text
+OK 1 messages:
1 653
```

Это подтверждает успешную POP3-аутентификацию и наличие одного сообщения в почтовом ящике на момент проверки.

**Примечание по безопасности:** на исходном снимке экрана были видны введённые пароли. В копии скриншота для материалов презентации строки с паролями скрыты. Пароль не приводится в отчёте.

## 7. Работа с Evolution

На клиентской машине открыт мастер создания почтовой учётной записи Evolution. На скриншоте видны имя `Suleim06` и начало ввода адреса электронной почты.

Также предоставлен скриншот окна создания исходящего сообщения с получателем `suleim06@suleim06.net` и темой `Proverka pochta`.

**Ограничение подтверждения:** снимок окна создания сообщения подтверждает подготовку письма, но не подтверждает его отправку или получение. Скриншот настроек Account Summary и скриншот полученного письма во входящих не предоставлены. Поэтому успешная доставка через Evolution в отчёте не заявляется.

## 8. Автоматизация развертывания

Предоставлен скриншот серверного скрипта `mail.sh`, содержащего команды установки Dovecot и Telnet, настройки `home_mailbox = Maildir/`, добавления правил firewalld и перезагрузки правил.

Предоставлен скриншот клиентского скрипта `mail.sh`, содержащего команду:

```bash
dnf -y install evolution
```

Скриншоты показывают содержимое фрагментов скриптов. Полный успешный повторный запуск provisioning-скриптов после внесения изменений отдельным скриншотом не подтверждён.
